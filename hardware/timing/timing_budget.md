## Sampling window (low-side shunts, sample at the PWM valley)

* Time needed between low-side turn-on and the sample: dead time + ringing + max(CSA settle, RC settle) = 1.70 us ([A] ringing 500 ns, [A] CSA settle 1.0 us).
* Largest sampleable duty: **0.932** (configured duty_max 0.98).
* Over all SVPWM angles at the configured voltage limit (0.95 x Vbus/sqrt(3)), the minimum number of phases with a valid window is **2**. Firmware rule: a phase is valid only when its duty is <= 0.932. With one invalid phase, the controller reconstructs it from the other two (`mc_currents_resolve`; reconstructed phase flagged, KCL residual unavailable). With two or more invalid phases, it would need to reduce duty_max; not reached at these values.

## Break (hardware shutdown) routing

| source | path | polarity | action |
|---|---|---|---|
| Gate-driver nFAULT (VDS over-current, UVLO, thermal, ...) [R] | PE15 TIM1_BKIN | active low, open drain + 10 k pull-up | MOE cleared asynchronously; outputs to idle state |
| Bus over-voltage comparator (TLV7041) | PC3 TIM1_BKIN2 | active low, open drain | as above |
| (option) MCU COMPx on CSA outputs | internal to TIM1_BKIN2 [R] | configurable | phase over-current without a pin; not used in the draft |

* Idle state: OSSI = 1, OISx = OISxN = 0, so every INHx/INLx is driven low and the driver holds all gates off. AOE = 0: MOE is never re-set automatically; only firmware does it, after a fault reset.
* BKF digital filter: 4 samples -> 24 ns added latency [D]. Measure the total input-to-gate-off latency at stage 3.

## Interrupt and task timing allocation

| priority | source | rate | budget | content |
|---|---|---|---|---|
| 0 (highest) | TIM1 BRK / BRK2 | event | < 2 us | latch fault flag; hardware has already stopped the outputs |
| 1 | ADC JEOC (injected end of conversion) | 20 kHz | <= 40 % of 50 us = 20 us | `mc_core_fast_step`: hall, currents, FOC, duty update (preloaded) |
| 2 | FDCAN RX FIFO | <= 2 kHz | <= 5 us | copy the frame to a queue; decoding runs in the slow task |
| 3 | SysTick / slow task | 1 kHz | <= 300 us | `mc_core_slow_step`, CAN RX decoding, TX polling, watchdog kick |
| background | idle | - | - | logging over UART (bench only) |

The fast-step cycle count is **not measured**. The host build shows no double-precision calls in `mc_core_fast_step` (objdump, MinSizeRel). It uses `sinf`/`cosf` from newlib. Measure DWT->CYCCNT around the ISR at stage 2 and replace `fast_isr_cycles_est`. If it exceeds the budget, use a table-based sin/cos, or run the FOC every second PWM period with ADC sampling every period.
