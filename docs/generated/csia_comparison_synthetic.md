> Synthetic sensors and faults (`host/csia_adapter/synthetic.py`). Shadow mode only. Generated by `tools/run_csia_study.py`. Not evidence about real sensors.

> **DEVELOPMENT SET (tuning data).** The adapter was designed and tuned on exactly these scenarios, so these numbers say nothing about generalisation. For held-out results, see `docs/csia/EVALUATION_RESULTS.md`.

Notes:
- Rotor-speed and power-balance relationships exist only while the motor drives through the freewheel; in this scenario the car coasts ~18 s between pulses, so detection of those faults waits for the next pulse (latency is regime-bound, reported, not hidden).
- B2 'first' times are NOT meaningful where B2 was already alarming on the fault-free run (e.g. rotor_vs_wheel_drive alarms during freewheel coasting): its detection is confounded by its nuisance rate.
- B2 raises an alarm on a residual but cannot say which sensor is wrong; B1 only sees stale/NaN/out-of-range values, so stuck-in-range, bias and gain faults pass it.
- Ambiguous ticks are periods where the evidence supports disagreement only; the adapter reports them instead of guessing.

Adapter + CSIA TrustCore tick time on this host (x86-64, CPython, HOST BENCHMARK - not a target measurement): mean 0.19 ms, max 1.40 ms at 10 Hz.
