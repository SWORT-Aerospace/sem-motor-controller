# Telemetry schema (canonical source and field contract)

Generated by `tools/telematics_schema.py` from `telematics/schema/telemetry_schema.yaml` (schema version 1, registry `reg-cbac7dc42d28`); do not edit. `--check` in CI validates the schema against the protocol, the adapter, the STLG record types of the host and the firmware, and the evidence model. Every controller signal is UNVERIFIED until the controller team states its frames; the semmc encodings are the simulation fixture.

## Evidence states

| State | Admissible | Meaning |
|---|---|---|
| `VALID` | yes | decoded, in range, confirmed by the source's validity flag when it has one, fresh |
| `SOURCE_UNVERIFIED` | no | in range but not confirmed: the source's validity flag is missing or stale, or the value is a bound (distance after lost edges) |
| `OUT_OF_RANGE` | no | outside the plausible range below: kept as evidence, value withheld |
| `TIMING_UNCERTAIN` | no | a valid value whose time is not known well enough for the use at hand (uncertainty or source timing beyond the consumer's tolerance) |
| `STALE` | no | the last value is older than its freshness threshold |
| `MISSING` | no | a supported signal that has not been received (since start or in the interval) |
| `INVALID` | no | the source marked it invalid (flag, sentinel), the frame failed its check, or a plausibility rule rejected it (suspect wheel channel) |
| `UNSUPPORTED` | no | this configuration cannot provide the signal (no adapter mapping, hardware not fitted, parameter unknown) |
| `UNKNOWN` | no | the source is present but the quantity cannot be determined (wheel with no edge: not standstill, not motion); an upper bound may be kept |

Measurement validity to state: `valid` -> `VALID`, `unverified` -> `SOURCE_UNVERIFIED`, `out_of_range` -> `OUT_OF_RANGE`, `invalid` -> `INVALID`, `decode_error` -> `INVALID`, `no_evidence` -> `UNKNOWN`, `stale` -> `STALE`, `missing` -> `MISSING`.

## Semantics

* **startup.** MISSING until the first sample; never a default value
* **stale.** after stale_s without a sample the live value is withheld and the state is STALE
* **missing.** a supported signal not received: MISSING, value null; never 0
* **unsupported.** a signal the configuration cannot provide (no adapter mapping, hardware not fitted, a parameter unknown): UNSUPPORTED, never MISSING
* **invalid.** INVALID with the reason (flag, sentinel, check, plausibility rule); value withheld

## Hall wheel input

* **valid pulse.** a falling edge that passes the 2 us input filter (TIM2 ICxF = 8 samples at 4 MHz) and is captured with its time
* **impossible interval.** an edge interval whose speed (pitch / interval) is above the plausible range (60 m/s): OUT_OF_RANGE, value withheld; edges closer than the filter are not captured
* **zero speed.** never concluded from the Hall channel alone: a held line cannot prove standstill (magnet under the sensor, short, failed sensor); standstill needs a source that can measure zero (vehicle context STOPPED)
* **no edge.** the channel reports but no edge came for longer than 3 periods: UNKNOWN (no_evidence) with the bound v < pitch / dt, which holds only for a working sensor
* **missing sensor.** a channel that never produced an edge: state N; its speed is UNKNOWN while no other channel moves, INVALID once another moves (suspect)
* **stale sensor.** records stop arriving (record counter gap, or no record within stale_s): STALE; lost records are counted
* **disconnected or stuck inactive.** silent for 8 periods and 1 s of a moving channel with the line at its inactive level: state I, speed INVALID, later distance a lower bound
* **stuck active.** the same with the line at its active level: state A (short to ground, failed sensor, magnet stuck)
* **rule.** the same integer rule in telematics/firmware/src/tm_wheel.c and host/telematics/wheel.py (tests: test_wheel_node_pit.py, test_firmware_host.py)

## Shared paths (common-cause candidates)

Common errors a disturbance of the path can give every source on it: loss (evidence stops), timing (times shift together), value (values shift together, so two sources can agree and both be wrong). A listed kind is a hypothesis the evidence has to rule out.

| Path | Feeds | Common errors | Evidence of a disturbance |
|---|---|---|---|
| `unit:recorder` | - | loss, timing | the session ends without a final counters record; the next session's reset cause is a brown-out or power-on reset; the counters show records or frames the unit could not log (log_dropped_queue, log_dropped_storage, can_not_logged) |
| `power:unit_supply` | `power:unit_5v`, `power:unit_3v3`, `unit:recorder` | loss, value | BOOT reset cause BOR or POR; a gap in the unit's records |
| `power:unit_5v` | - | loss, value | GNSS records stop together with other 5 V loads |
| `power:unit_3v3` | `power:sensor_supply` | loss, value | IMU and TMP117 reads fail together; BOOT reset cause BOR |
| `power:sensor_supply` | - | loss, value | every wheel channel silent or stuck together |
| `bus:i2c1` | - | loss, timing | IMU and TEMP reads fail together while wheel capture continues |
| `bus:vehicle_can` | - | loss, timing | every controller message stops together; FDCAN error counters rise |
| `clock:tim2` | - | timing, value | record time not monotonic; status-line time jumps |
| `ground:unit_ground` | - | loss, value | edges or reads fail on several inputs at once while the supply holds |
| `antenna:gnss` | - | loss, value | fix lost or speed accuracy degraded (gnss.speed_acc) |
| `power:controller_supply` | - | loss | every controller message stops |
| `ground:vehicle_can_ground` | - | loss, value | CAN error counters rise |

## Vehicle contexts

| Context | Needs | Rule |
|---|---|---|
| `STARTUP` | - | the first seconds after boot, or until any motion evidence is VALID |
| `STOPPED` | `gnss.speed` (or `ctrl.motor_speed`) | a source that can measure zero says \|v\| below the stop threshold; the Hall channel alone never shows STOPPED |
| `LAUNCH` | `any_speed`, `propulsion_effort` | speed below the launch ceiling and rising, with propulsion effort |
| `CRUISE` | `any_speed` | speed above the low-speed floor and \|dv/dt\| below the cruise band |
| `COAST` | `any_speed`, `propulsion_effort` | speed above the floor, no propulsion effort, decelerating |
| `BRAKE` | `brake_signal` | not determinable: no brake signal is received; deceleration alone cannot tell braking from grade or drag |
| `READY` | `ctrl.state with the controller team's state meanings` | not determinable until the controller team defines its state codes |
